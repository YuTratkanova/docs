# Руководство по CloudWatch

CloudWatch - это сервис AWS для мониторинга и логирования. Используется для диагностики проблем и анализа работы системы PandaPay.

## Что такое CloudWatch

CloudWatch хранит логи всех операций системы:
- API запросы и ответы
- Ошибки и исключения
- Автоматические операции
- Обработка заявок
- Выполнение выплат

<Info>
CloudWatch логи доступны администраторам для диагностики проблем и анализа работы системы.
</Info>

## Доступ к CloudWatch

### Через AWS Console

<Steps>
<Step title="Войдите в AWS Console">
  Откройте [AWS Console](https://console.aws.amazon.com) и войдите в аккаунт.
</Step>

<Step title="Перейдите в CloudWatch">
  В меню сервисов найдите "CloudWatch" или используйте поиск.
</Step>

<Step title="Откройте Logs">
  В левом меню выберите "Logs" → "Log groups".
</Step>

<Step title="Выберите log group">
  Найдите log group для вашего сервиса (например, `/aws/lambda/pandapay-api`).
</Step>
</Steps>

## Поиск логов

### Поиск по времени

1. Выберите временной диапазон в правом верхнем углу
2. Используйте стрелки для навигации по времени
3. Выберите "Custom range" для точного диапазона

### Поиск по ключевым словам

В поле "Filter events" введите:
- `order_id` - найти логи конкретной заявки
- `user_id` - найти логи пользователя
- `ERROR` - найти все ошибки
- `dispute` - найти логи связанные со спорами

### Примеры фильтров

```
order_id:123456
ERROR
status:completed
amount>1000
```

## Поиск информации о заявке

<Steps>
<Step title="Откройте CloudWatch Logs">
  Перейдите в CloudWatch → Logs → Log groups.
</Step>

<Step title="Выберите временной диапазон">
  Выберите время, когда была создана или обрабатывалась заявка.
</Step>

<Step title="Используйте фильтр">
  В поле фильтра введите: `order_id:YOUR_ORDER_ID`
  
  Например: `order_id:order_abc123`
</Step>

<Step title="Просмотрите результаты">
  В результатах вы увидите все логи связанные с этой заявкой:
  - Создание заявки
  - Изменение статуса
  - Обработка платежа
  - Завершение заявки
</Step>
</Steps>

## Анализ логов

### Поиск ошибок

Используйте фильтр `ERROR` для поиска всех ошибок:

```
ERROR
```

Или комбинацию:
```
ERROR order_id:123456
```

### Проверка операций с балансом

Для поиска операций с балансом:
```
balance
operation_type:order
```

### Проверка уведомлений

Для поиска логов отправки уведомлений:
```
notification
telegram
callback
```

## Экспорт логов

### Скачать логи

1. Выберите нужные логи из результатов
2. Нажмите "Actions" → "Export to S3" (если настроено)
3. Или используйте "Download" для скачивания в формате JSON

### Использование AWS CLI

```bash
aws logs tail /aws/lambda/pandapay-api --since 1h --filter-pattern "ERROR"
```

## Типичные сценарии

### Сценарий 1: Заявка не завершается

**Что искать:**
```
order_id:YOUR_ORDER_ID
```

**Проверьте:**
- Есть ли логи об обработке платежа
- Есть ли ошибки при обработке
- Пришло ли уведомление от банка

### Сценарий 2: Баланс не обновляется

**Что искать:**
```
balance user_id:123
order_id:YOUR_ORDER_ID
```

**Проверьте:**
- Была ли операция создана
- Есть ли ошибки при обновлении баланса
- Какой статус операции

### Сценарий 3: Callback не приходит

**Что искать:**
```
callback order_id:YOUR_ORDER_ID
notification
```

**Проверьте:**
- Была ли попытка отправить callback
- Есть ли ошибки при отправке
- Какой URL использовался

## Советы по работе с логами

<Warning>
Логи могут содержать чувствительную информацию. Не делитесь полными логами публично.
</Warning>

<Info>
Для лучшей производительности используйте фильтры по времени и ключевым словам вместо просмотра всех логов.
</Info>

### Лучшие практики

1. **Используйте фильтры** - не просматривайте все логи, используйте фильтры по времени и ключевым словам
2. **Сохраняйте важные логи** - экспортируйте или копируйте важные логи для дальнейшего анализа
3. **Проверяйте временные метки** - убедитесь что ищете в правильном временном диапазоне
4. **Используйте несколько фильтров** - комбинируйте фильтры для точного поиска

## Альтернативные способы поиска

### Через админ-панель

Некоторые логи доступны напрямую в админ-панели:
- История операций
- Детали заявок
- Информация о спорах

### Через API

Используйте API для получения информации:
- `GET /order/{id}` - детали заявки
- `GET /balance/history` - история баланса

## Частые вопросы

<AccordionGroup>
  <Accordion title="Как долго хранятся логи в CloudWatch?">
    Логи хранятся согласно настройкам retention policy (обычно 7-30 дней). Для более длительного хранения используйте экспорт в S3.
  </Accordion>
  <Accordion title="Как найти логи конкретной операции?">
    Используйте фильтр по `order_id` или другим уникальным идентификаторам операции.
  </Accordion>
  <Accordion title="Что делать если не могу найти логи?">
    Проверьте временной диапазон, убедитесь что используете правильный log group, и попробуйте более широкий фильтр.
  </Accordion>
</AccordionGroup>
