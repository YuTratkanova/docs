# База данных

PandaPay использует PostgreSQL как основную систему управления базами данных.

## Технология

- **СУБД:** PostgreSQL
- **Драйвер:** стандартный Go драйвер для PostgreSQL
- **Миграции:** Go migrate или аналогичный инструмент

### Заявки (Orders)

Таблица `orders` содержит информацию о всех заявках:
- ID заявки
- ID мерчанта
- ID трейдера (если заявка принята)
- Сумма и валюта
- Статус заявки
- Дата создания и обновления
- Реквизиты и детали операции

### Балансы

Таблица `balance_history` хранит историю всех операций с балансом:
- Тип операции (order, payout, topUp, etc.)
- Сумма
- Баланс до и после операции
- Связанная заявка или операция
- Временная метка

### Споры (Disputes)

Таблица `disputes` для управления спорами:
- ID спора
- Связанная заявка
- Статус спора
- Решение администратора
- Временные метки

### Реквизиты

Таблица `requisites` для банковских реквизитов трейдеров:
- ID реквизита
- ID трейдера
- Банк
- Номер счета
- Валюта и страна
- Статус (активен/неактивен)

## Миграции

### Структура миграций

Миграции находятся в: `internal/database/migrations`

<Info>
Миграции управляют структурой базы данных и изменениями схемы.
</Info>

### Применение миграций

```bash
# Поднять все миграции
migrate -path ./internal/database/migrations \
  -database "postgresql://user:password@host:port/dbname" up

# Откатить последнюю миграцию
migrate -path ./internal/database/migrations \
  -database "postgresql://user:password@host:port/dbname" down 1
```

### Создание новой миграции

```bash
migrate create -ext sql -dir ./internal/database/migrations -seq add_new_table
```

## Основные связи

```
users
├── orders (merchant_id, trader_id)
├── balance_history (user_id)
├── requisites (trader_id)
└── disputes (through orders)

orders
├── balance_history (order_id)
└── disputes (order_id)
```

## Индексы

Для оптимизации производительности используются индексы на:
- `orders.merchant_id`
- `orders.trader_id`
- `orders.status`
- `orders.created_at`
- `balance_history.user_id`
- `balance_history.order_id`
- `disputes.order_id`

## Транзакции

Критические операции выполняются в транзакциях для обеспечения целостности данных:
- Создание заявки и обновление баланса
- Завершение заявки и начисление выплаты
- Разрешение спора и обновление балансов

## Advisory Locks

Система использует PostgreSQL advisory locks для:
- Предотвращения дублирования заявок
- Блокировки трейдеров при принятии заявки
- Гарантии атомарности операций

## Резервное копирование

<Warning>
Регулярно создавайте резервные копии базы данных для защиты данных.
</Warning>

### Создание резервной копии

```bash
pg_dump -h hostname -U username -d dbname > backup.sql
```

### Восстановление

```bash
psql -h hostname -U username -d dbname < backup.sql
```

## Мониторинг

### Проверка производительности

Используйте PostgreSQL встроенные инструменты для мониторинга:
- `pg_stat_activity` - активные соединения
- `pg_stat_database` - статистика базы данных
- `EXPLAIN ANALYZE` - анализ запросов

### Важные запросы для диагностики

#### Проверка активных блокировок

```sql
SELECT * FROM pg_locks WHERE NOT granted;
```

#### Проверка advisory locks

```sql
SELECT * FROM pg_advisory_locks;
```
