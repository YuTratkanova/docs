# Безопасность

PandaPay реализует множество мер безопасности для защиты данных и операций пользователей.

## Аутентификация

### JWT токены

Система использует JWT (JSON Web Tokens) для аутентификации пользователей:

- Токены имеют срок действия (expiration time)
- Токены подписываются секретным ключом
- Refresh токены для обновления доступа

<Warning>
Никогда не передавайте токены в открытом виде. Всегда используйте HTTPS.
</Warning>

### Получение токена

```bash
POST /auth/login
Content-Type: application/json

{
  "email": "user@example.com",
  "password": "password"
}
```

**Ответ:**
```json
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "expires_in": 3600
}
```

### Использование токена

```bash
GET /api/endpoint
Authorization: Bearer {token}
```

## Защита API

### HTTPS

Все API запросы должны использовать HTTPS для защиты данных при передаче.

<Warning>
HTTP запросы могут перехватываться. Всегда используйте HTTPS в продакшене.
</Warning>

### Rate Limiting

API защищено от злоупотреблений через rate limiting:
- Ограничение количества запросов на пользователя
- Ограничение по IP адресу
- Блокировка при подозрительной активности

### Валидация входных данных

Все входные данные валидируются:
- Проверка типов данных
- Проверка диапазонов значений
- Проверка форматов (email, URL, etc.)
- Санитизация для предотвращения инъекций

## Защита данных

### Хранение паролей

Пароли хранятся в зашифрованном виде:
- Использование хеширования (bcrypt или аналогичное)
- Соль (salt) для каждого пароля
- Пароли никогда не хранятся в открытом виде

### Шифрование чувствительных данных

Чувствительные данные шифруются:
- Реквизиты банковских счетов
- Токены и ключи
- Персональные данные

### Безопасное хранение секретов

Секреты хранятся безопасно:
- Использование переменных окружения
- AWS Secrets Manager для продакшена
- Никогда не коммитить секреты в Git

## Callback подпись

### Проверка подписи

Для безопасности callback уведомлений используется подпись:

```javascript
function verifyCallback(body, signature, secret) {
  const hash = crypto
    .createHmac('sha256', secret)
    .update(JSON.stringify(body))
    .digest('hex');
  
  return hash === signature;
}
```

<Warning>
Всегда проверяйте подпись callback запросов для предотвращения подделки.
</Warning>

## Защита от SQL инъекций

### Параметризованные запросы

Все SQL запросы используют параметризацию:

```go
// Правильно
db.Query("SELECT * FROM users WHERE id = $1", userID)

// Неправильно - уязвимость к SQL инъекции
db.Query("SELECT * FROM users WHERE id = " + userID)
```

## Защита от XSS

### Санитизация HTML

Все пользовательские данные санитируются перед выводом:
- Экранирование специальных символов
- Валидация HTML контента
- CSP (Content Security Policy) заголовки

## Мониторинг безопасности

### Логирование событий

Система логирует важные события:
- Неудачные попытки входа
- Подозрительная активность
- Изменения прав доступа
- Критические операции

### Алерты

Настроены алерты на:
- Множественные неудачные попытки входа
- Необычные паттерны активности
- Изменения в конфигурации безопасности

## Рекомендации для разработчиков

### Для мерчантов

- Используйте HTTPS для всех запросов
- Храните токены безопасно
- Проверяйте подпись callback запросов
- Регулярно обновляйте токены

### Для администраторов

- Используйте сложные пароли
- Включайте двухфакторную аутентификацию (если доступно)
- Регулярно проверяйте логи на подозрительную активность
- Ограничивайте доступ к админ-панели по IP

## Соответствие стандартам

Система следует лучшим практикам безопасности:
- OWASP Top 10 рекомендации
- Стандарты PCI DSS (для платежных данных)
- GDPR требования (для персональных данных)
